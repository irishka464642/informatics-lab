# Єдиний приймач результатів для 5–9 класів

Один Google Apps Script записує результати інтерактивних ігор **у 5 різних журналах** (5, 6, 7, 8, 9 класи). Усередині кожного журналу створюються вкладки **за датами уроків** у вигляді `ДД.ММ.РРРР`. Для різних літер одного класу (наприклад, 5-А, 5-Б, 5-В) застосовується той самий журнал, але значення класу й групи записуються в окремі колонки.

## Де журнали

На **робочому** Google Диску `galeeva@chern12.ukr.education`, папка **«8 класи» → «Результати»**. У ній є рівно п'ять журналів. Ключовий журнал **8 класу** містить вкладку **«Реєстр журналів»** з адресами всіх п'яти таблиць. ID журналів зберігаються приватно **в Google Таблиці та Script Properties**, а не в публічному GitHub.

## Поточна адреса спільного приймача

Універсальний вебзастосунок розгорнуто за адресою:

`https://script.google.com/macros/s/AKfycbzvbbCnwgogkdFa8CRKy6lpWtMJU9--KOcLwV3F6MtBQfRRDjtdrpQFXfjeluU2JijC9Q/exec`

Це **одна й та сама URL** для всіх ігор 5–9 класів. У HTML кожної гри використовуйте:

```js
const RESULTS_ENDPOINT = 'https://script.google.com/macros/s/AKfycbzvbbCnwgogkdFa8CRKy6lpWtMJU9--KOcLwV3F6MtBQfRRDjtdrpQFXfjeluU2JijC9Q/exec';
```

Адреса вже вставлена в обидві гри уроків №21–22 для 8 класу. **Тестовий запис у таблицю ще треба перевірити**. У браузері `no-cors` не підтверджує успішність збереження.

## Одноразове налаштування — необхідні кроки власника

1. Відкрийте на робочому диску **«Інформатика 8 клас — загальний журнал результатів інтерактивних ігор»**.
2. **Розширення → Apps Script**. Видаліть тестовий код і повністю вставте в `Code.gs` актуальний файл [Code.gs](./Code.gs). **Збережіть.**
3. У верхньому списку функцій оберіть **`setupJournalRouter`**, натисніть **Виконати / Run** і надайте Google-дозволи. Ця функція зчитує вкладку «Реєстр журналів», перевіряє доступ до всіх 5 журналів та зберігає їхні ID у **Script Properties**. У журналі виконання має з'явитися «Підключено 5 журналів».
4. **Розгорнути → Нове розгортання → Вебзастосунок**. Виконувати від імені: **вас / власника**. Доступ: за політикою школи. Для учнів без авторизованого Google-акаунта може знадобитися **Anyone**, лише якщо це дозволено закладом.
5. Скопіюйте URL, що завершується на `/exec`. Відкрийте його: статус має містити `"configured":true`.
6. Надішліть URL `/exec` у чат, щоб установити його в іграх. Після цього в усіх іграх використовується **одна й та сама** адреса.

**Далі для нових уроків нічого на сервері не розгортаємо:** у новій HTML-грі передаємо `lessonDate`, `lessonId`, `gameTitle` і завдання з результатом. Якщо коли-небудь заміните одну з п'яти таблиць, оновіть її ID у вкладці «Реєстр журналів» і знову вручну запустіть `setupJournalRouter`; URL /exec не змінюється.

## Формат запису з гри (єдиний стандарт)

```json
{
  "apiVersion": 1,
  "klass": "8-А",
  "group": "1",
  "surname": "Приклад",
  "firstname": "Учень",
  "lessonDate": "2026-11-20",
  "lessonId": "21-22",
  "gameTitle": "TRUE чи FALSE? Зламай код логіки",
  "taskNo": "Місія 2 / запитання 1",
  "progress": 3,
  "maxProgress": 12,
  "score": 1,
  "maxScore": 1,
  "firstTry": 2,
  "questionMisses": 0,
  "totalMisses": 1,
  "eventId": "sample-session-123456-3",
  "sessionId": "sample-session-123456"
}
```

- `klass` обов'язково містить номер від **5 до 9** і літеру класу кирилицею: `5-А`, `6-Б`, `7-В`, `8-А`, `9-Б` тощо.
- `group` — `1`, `2`, `3`, `4` або порожнє значення, якщо група не застосовується.
- `lessonDate` — дата уроку **YYYY-MM-DD**. Вона визначає назву вкладки, а номер класу визначає потрібний журнал. Різні класи можуть мати різні дати одного уроку.
- `eventId` — **незмінний унікальний ID** для конкретного завершеного завдання. Повторне надсилання тієї самої події не дублює запис.
- `progress` і `maxProgress` — прогрес; `score` і `maxScore` — бали за цей етап. Прогрес **не є автоматичною шкільною оцінкою**.

## Відправлення після кнопки «Наступне завдання»

```js
const RESULTS_ENDPOINT = "https://script.google.com/macros/s/.../exec";

async function submitResult(event) {
  await fetch(RESULTS_ENDPOINT, {
    method: "POST",
    mode: "no-cors",
    headers: {"Content-Type": "text/plain;charset=UTF-8"},
    body: JSON.stringify(event)
  });
}
```

У грі потрібно зберігати результат **локально в черзі** перед надсиланням і повторювати спробу за потреби. Запит у режимі `no-cors` не повертає доступного JavaScript підтвердження запису — вчитель перевіряє результат у Google Таблиці. **Не показуйте «Збережено в таблиці» тільки через успішне виконання fetch.**

## Наявна гра 8 класу

Гра «TRUE чи FALSE? Зламай код логіки» (уроки 21–22) уже готує такий формат подій:
- `8-А` → `2026-11-20` (вкладка `20.11.2026`);
- `8-Б` → `2026-11-23` (вкладка `23.11.2026`).

Реальна адреса `/exec` вже встановлена у грі теорії та у практичній грі. Після виконання завдання потрібно перевірити, що запис фактично з'явився у відповідній таблиці.

## Безпека й приватність

Таблиці можуть містити персональні дані неповнолітніх — **не публікуйте журнали та реєстр**. У режимі `Anyone` відправник **не проходить перевірку особи**; хтось може надсилати неправдиві записи або повторювати запити. За потреби використовуйте шкільні акаунти чи псевдоніми, а записи не сприймайте як єдиний доказ для оцінювання.

**Важливо:** GitHub містить тільки джерельний код. URL опублікованого Apps Script надано власником робочого акаунта. Потрібно переконатися, що в серверному коді виконано `setupJournalRouter()`: відкрийте `/exec` і перевірте поле `configured: true`. Роботу end-to-end підтверджує лише наявність тестового запису в потрібному журналі.
